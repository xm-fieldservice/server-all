## 🎯 设计背景

### 核心挑战

在总数据底座场景下,需要管理多种类型的数据:
- 开发文档 (技术类)
- 现场服务数据 (业务类)
- 内勤管理数据 (行政类)
- 个人日记 (生活类)

**关键问题:**
1. 如何避免不相关数据被错误关联? (例如"开发任务"和"打酱油")
2. 如何支持PC端结构化录入和手机端快速录入?
3. 如何补齐手机端录入的不完整标签?

## 📊 术语定义

### 标签体系分类

```
结构化标签 (狭义标签)
├─ 预定义的、显性的标签
├─ 例如: type, project, domain, priority
└─ 特点: 规范、可控、易查询

动态标签 (广义标签)
├─ AI/图谱生成的、隐性的标签
├─ 例如: ai_keywords, ai_entities, semantic_cluster
└─ 特点: 灵活、自适应、发现隐藏关系
```

### 关系类型

```
显性关系
├─ 直接存储在节点属性中
├─ 例如: node.project = "project-a"
└─ 查询: MATCH (n {project: 'project-a'})

隐性关系
├─ 通过图结构遍历推导
├─ 例如: (child)-[:HAS_CHILD*]->(parent)
└─ 查询: MATCH (n)-[:HAS_CHILD*]->(root)
```

```javascript
{

数据流:
┌────────────────────────┐
│ 项目A (根节点)          │
│ type: Project          │
│ domain: 开发           │
│ tags: [重要, Q4]       │
└────────────────────────┘
         ↓ 自动继承
┌────────────────────────┐
│ 任务1 (子节点)          │
│ type: Task             │ ← 新类型
│ project: project-a     │ ← 继承(显性)
│ domain: 开发           │ ← 继承(显性)
│ parent: project-a      │ ← 结构关系
│ tags: [重要, Q4]       │ ← 继承(可选)
└────────────────────────┘
```

**实现代码:**

```javascript
function createChildNode(parentId, childData) {
  const parent = getNode(parentId);
  
  const child = {
    ...childData,
    // 显性继承
    project: parent.project || parent.id,
    domain: parent.domain,
    department: parent.department,
    tags: [...parent.tags],  // 继承父标签
    // 结构关系
    parent: parentId
  };
  
  return child;
}
```

### 阶段2: 后台批量分析

**定期运行的图谱分析:**

```javascript
// 每天凌晨运行
async function batchAnalyzeUntagged() {
  // 1. 查找待审核节点
  const nodes = await findNodes({
    needs_review: true,
    device: "mobile"
  });
  
  // 2. 基于图谱上下文重新分析
  for (const node of nodes) {
    // 查找语义相似的已标记节点
    const similar = await findSimilarNodes(node.content, {
      min_similarity: 0.7,
      has_project: true  // 必须有明确的project标签
    });
    
    // 统计最可能的项目
    const projectVotes = {};
    similar.forEach(s => {
      projectVotes[s.project] = (projectVotes[s.project] || 0) + s.similarity;
    });
    
    // 更新推断
    const bestProject = Object.keys(projectVotes).sort((a,b) => 
      projectVotes[b] - projectVotes[a]
    )[0];
    
    await updateNode(node.id, {
      inferred_project: bestProject,
      confidence_project: projectVotes[bestProject] / similar.length,
      similar_nodes: similar.map(s => s.id),
      analyzed_at: new Date()
    });
  }
}
```

## 🔄 级联补齐机制

### 核心概念

**级联补齐**: 一旦确认节点属于某个项目,自动继承该项目的所有结构化标签。

### 实现流程

```javascript
async function confirmProject(nodeId, projectId) {
  // 1. 获取项目的所有结构化标签
  const project = await getNode(projectId);
  
  // 2. 提取可继承的标签
  const inheritableTags = {
    // 核心标签 - 必须继承
    project: project.id,
    domain: project.domain,
    department: project.department,
    
    // 可选标签 - 可以继承
    priority: project.priority,
    owner: project.owner,
    tech_stack: project.tech_stack,
    deadline: project.deadline,
    
    // 用户标签 - 合并(不覆盖)
    tags: [...project.tags]
  };
  
  // 3. 获取当前节点
  const node = await getNode(nodeId);
  
  // 4. 级联补齐
  const updatedNode = {
    ...node,
    
    // 补齐结构化标签
    ...inheritableTags,
    
    // 合并用户标签(去重)
    tags: [...new Set([...node.tags, ...inheritableTags.tags])],
    
    // 清除推断标记
    inferred_project: null,
    needs_review: false,
    
    // 记录补齐信息
    completed_at: new Date(),
    completed_by: "user",
    inherited_from: projectId
  };
  
  // 5. 保存
  await updateNode(nodeId, updatedNode);
  
  // 6. 创建关系
  await createRelation(projectId, nodeId, "CONTAINS");
  
  return updatedNode;
}
```

## 🎯 AI工作边界

### 结构化标签的边界

```javascript
// 结构化标签 - AI不应修改
const SYSTEM_TAGS = {
  project: "project-a",    // 项目归属 - 固定
  domain: "开发",          // 业务域 - 固定
  type: "Task",            // 类型 - 固定
  parent: "project-a"      // 父节点 - 固定
};

// AI的工作范围
const AI_SCOPE = {
  // 可以做的
  can_add: ["ai_keywords", "ai_entities", "related_nodes"],
  can_suggest: ["tags", "priority"],  // 建议,但不自动修改
  
  // 不能做的
  cannot_modify: ["project", "domain", "type", "parent"],
  
  // 跨越边界的规则
  cross_domain: false,     // 不跨业务域
  cross_project: true,     // 可以关联其他项目
  max_depth: 2             // 关系挖掘最大深度
};
```

## 🔍 查询策略

### 快速查询 - 使用结构化标签

```cypher
// 查询项目A的所有任务
MATCH (n:Task {project: 'project-a'})
RETURN n

// 查询开发域的高优先级任务
MATCH (n:Task {domain: '开发', priority: '高'})
RETURN n
```

### 深度查询 - 结合动态标签

```cypher
// 查询与"性能优化"相关的任务
MATCH (n:Task)
WHERE 'performance' IN n.ai_keywords
RETURN n

// 查询项目A及其关联的所有节点(通过AI发现的关系)
MATCH (n {project: 'project-a'})
MATCH (n)-[:AI_RELATED*1..2]-(m)
RETURN n, m
```

### 混合查询 - 显性+隐性

```cypher
// 查询项目A的任务,包括通过父子关系间接关联的
MATCH (n:Task)
WHERE n.project = 'project-a'  // 显性
   OR (n)-[:HAS_CHILD*]->(root:Project {id: 'project-a'})  // 隐性
RETURN n
```

## 🎯 关键设计原则

### 1. 分层设计
- 结构化标签和动态标签分离
- 各层职责清晰,互不干扰

### 2. 渐进式补齐
- 手机端: 快速录入,最少标签
- AI推断: 实时轻量级分析
- 后台分析: 深度图谱挖掘
- 人工审核: 最终确认补齐

### 3. 置信度驱动
- 高置信度: 批量确认
- 中置信度: 逐个审核
- 低置信度: 人工决策或舍弃

### 4. 级联继承
- 一旦确认项目归属
- 自动继承所有项目标签
- 实现真正的"补齐"

### 5. 边界清晰
- AI只在动态标签层工作
- 不修改结构化标签
- 只提供建议,不自动决策
