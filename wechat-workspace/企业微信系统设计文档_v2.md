# 企业微信系统设计文档 v2（对齐AI工厂V3四层隔离）

## 0. 目标与范围
- 统一企业微信消息/笔记/问答的接入、持久化与检索，复用 AI 工厂记忆系统（entries + entry_embeddings + chat_sessions/messages）。
- 强制四层隔离（user_id / agent_type / agent_instance_id / session_id），与 RLS 策略一致。
- 消除内存存储，全部落库；补齐安全、鉴权、配置、可观测性。

## 1. 总体架构
```
WeCom 回调 → wecom_gateway (FastAPI) → entries_ingest API → ai-factory (entries + embeddings + RLS)
                               ↘ chat_sessions/chat_messages 持久化（短期层）
```
- wecom_gateway 仅做接入与标准化，不做业务切片；泳道/知识萃取由 AI 工厂侧完成。
- 所有下游调用显式传隔离上下文：user_id、agent_type、agent_instance_id、session_id。

## 2. 隔离与安全
- 四层隔离字段：`user_id`, `agent_type`, `agent_instance_id`, `session_id`（必填）。
- RLS：入口不依赖宽松 NULL 透传；AI 工厂侧策略匹配三层（user/agent_type/agent_instance_id），入口必须传全量。
- 会话 ID：`session_id = wecom:{chat_id或from_user}`；群聊可用 `wecom:group:{room_id}`。
- Agent 定义：
  - Note Bot：`agent_type=wecom_note_bot`; `agent_instance_id=dept_{dept_id}_note`（无部门时用 `dept_default`）。
  - QA Bot：`agent_type=wecom_qa_bot`; `agent_instance_id=dept_{dept_id}_qa`。
- 配置校验：启动时必须存在 `WECOM_CALLBACK_TOKEN / WECOM_ENCODING_AES_KEY / WECOM_CORP_ID / WECOM_APP_SECRET / WECOM_QA_AGENT_ID / WECOM_NOTE_AGENT_ID / AI_FACTORY_BASE_URL`，缺失则拒绝启动。
- 回调校验：严格验签，失败返回 403；加密模式必须 AES 解密，失败不应返回 success。

## 3. 数据流与入库契约
### 3.1 Note / QA 消息 → entries_ingest
- URL：`{AI_FACTORY_BASE_URL}/entries/ingest`
- Payload 关键字段：
  - `raw_text`: 去前缀后的正文；
  - `user_id`: `wecom:{userid}`；
  - `agent_type`, `agent_instance_id`, `session_id`（必填）；
  - `note_datetime`/`message_ts`: ISO8601；
  - `scene_tags`: `{channel: "wecom:note_bot"|"wecom:qa_bot", semantic_type: "note"|"qa_question"|"qa_answer", peer, conversation, department?, project?}`；
  - `extra_context`: `{source_channel:"wecom", source_app, wecom:{userid, msgid, department_id, agent_id, room_id?}, tags_snapshot?}`。
- 返回非 2xx 需记录错误并可选重试（幂等由下游保障）。

### 3.2 聊天记录 → chat_sessions/chat_messages
- 同时写入短期层：
  - `chat_sessions`: session_id(wecom:xxx), user_id, agent_type, agent_instance_id, created_at；
  - `chat_messages`: message_id(wecom_msg_xxx), session_id, user_id, agent_type, agent_instance_id, role, content, created_at, metadata（含 wecom msgid/agentid/roomid）。
- 确保与 entries_ingest 的隔离上下文一致。

### 3.3 群聊/客服小群
- 移除内存 `MESSAGES/CONVERSATIONS`；改为持久化：
  - 群元数据表（room_id, name, type, participants, created_at, created_by）。
  - 群消息表（message_id, room_id, sender_id, content, msg_type, created_at, metadata）。
- 对接 entries/聊天表的 user/agent_type/instance/session 映射：`session_id = wecom:group:{room_id}`。

## 4. 模块设计（wecom_gateway）
- `app.py`：入口、回调、调试接口，负责验签、解密、标准化 payload、调用 ingest / chat 持久化。
- `handlers/qa_bot.py` / `note_bot.py`：按 AgentID 路由，组装隔离上下文，调用 ingest。
- `group_chat.py`：群聊持久化与视图；去除内存态。
- `wecom_org.py`：组织/部门同步（用于 agent_instance_id 生成与标签补充）。
- `registry.py`：AgentID → handler 注册表。

## 5. 配置与部署
- 环境变量：
  - `AI_FACTORY_BASE_URL`、`WECOM_*`（Token/EncodingAESKey/CorpID/Secret/AgentIDs）。
  - 数据库：`PG_HOST/PG_PORT/PG_DB/PG_USER/PG_PASSWORD`（用于群聊/会话落库）。
- 依赖声明：`fastapi`, `uvicorn`, `requests`, `pycryptodome`, `pydantic`, `mcp`（如用）, `psycopg[binary,pool]` 或 ORM（选型），`python-dotenv`。
- 运行：`uvicorn wecom_gateway.app:app --host 0.0.0.0 --port 8000`（dev）；前置 Nginx 做 HTTPS 和路径转发。

## 6. 安全与合规
- 不在代码中硬编码密钥；使用 env + k8s secret / dotenv 管理。
- 回调验签必选；解密失败/签名失败返回 403，不吞错。
- 日志脱敏：不打印密钥、Token、Encrypt 全文；仅输出前缀摘要。
- 限流与重试：对外接口加限流（Nginx/中间件）；下游调用设置超时与有限次重试。

## 7. 可观测性
- 结构化日志：按 info/warn/error；记录 msg_id、session_id、agent_id、userid。
- 指标：入口 QPS、失败率、调用 AI 工厂耗时、验签失败计数、下游重试计数。
- 健康检查：`/health` 返回依赖检查（env、数据库连通、AI_FACTORY_BASE_URL 探活可选）。

## 8. 测试策略
- 单元测试：验签/解密函数、handler 组装 payload、失败路径（缺 env / 下游 5xx）。
- 集成测试：
  - `/wecom/callback` 加密/明文用例；
  - Note/QA 入口 → entries_ingest 200；
  - 会话/群聊持久化写入与隔离字段校验；
  - AgentID 路由正确性。
- 回归测试：隔离/RLS 验证（查询只返回本上下文数据）。
