# V3多租户架构升级执行指南

## 📋 升级概述

- **升级版本**: V3.0
- **升级内容**: 四层数据隔离 + Knowledge Node 四级结构
- **升级文件**: `upgrade_v3_with_admin.sql`
- **执行方式**: 使用数据库管理员权限执行

## 🎯 升级内容清单

### 1. 创建缺失的表
- ✅ `chat_sessions` - 会话表
- ✅ `chat_messages` - 消息表
- ✅ `chat_sections` - 会话分段表
- ✅ `qa_query_index` - Q&A缓存表

### 2. 添加四层隔离字段
- ✅ `user_id` - 用户ID（第1层）
- ✅ `agent_type` - Agent类型（第2层）
- ✅ `agent_instance_id` - Agent实例ID（第3层）
- ✅ `section_id` - 会话分段ID（第4层）

### 3. 添加 Knowledge Node 四级结构字段
- ✅ `title` - Level 1: 身份标识
- ✅ `summary_ai` - Level 2: 核心语义
- ✅ `content` - Level 3: 事实依据
- ✅ `scene_tags` - Level 4: 场景标签
- ✅ `extra_meta` - Level 4: 附加元数据

### 4. 创建索引（13个）
- ✅ 四层隔离索引（6个）
- ✅ Knowledge Node 索引（5个）
- ✅ 查询性能索引（2个）

### 5. 启用RLS行级安全
- ✅ 为 `entries` 表启用行级安全策略

## 🚀 执行步骤

### 方式1：使用psql命令行执行（推荐）

```bash
# 1. 备份数据库（重要！）
pg_dump -h localhost -p 5433 -U postgres rag_db > backup_$(date +%Y%m%d_%H%M%S).sql

# 2. 执行升级脚本
psql -h localhost -p 5433 -U postgres -d rag_db -f upgrade_v3_with_admin.sql

# 3. 验证升级结果
psql -h localhost -p 5433 -U postgres -d rag_db -c "\d entries"
psql -h localhost -p 5433 -U postgres -d rag_db -c "\d chat_sessions"
psql -h localhost -p 5433 -U postgres -d rag_db -c "\d chat_sections"
psql -h localhost -p 5433 -U postgres -d rag_db -c "\d qa_query_index"
```

### 方式2：使用Python脚本执行

```bash
# 1. 修改数据库配置（使用管理员用户）
export AI_PG_USER=postgres
export AI_PG_PASSWORD=your_postgres_password

# 2. 执行Python升级脚本
python3 upgrade_db_v3.py

# 3. 查看日志验证结果
```

### 方式3：在Docker容器中执行

```bash
# 1. 进入PostgreSQL容器
docker exec -it <postgres_container_name> bash

# 2. 连接到数据库
psql -U postgres -d rag_db

# 3. 执行升级脚本
\i /path/to/upgrade_v3_with_admin.sql

# 4. 验证结果
\d entries
```

## ✅ 升级验证

### 1. 检查表结构

```sql
-- 查看 entries 表结构
\d entries

-- 查看 chat_sessions 表结构
\d chat_sessions

-- 查看 chat_sections 表结构
\d chat_sections

-- 查看 qa_query_index 表结构
\d qa_query_index
```

### 2. 检查索引

```sql
-- 检查所有相关索引
SELECT
    schemaname,
    tablename,
    indexname,
    indexdef
FROM pg_indexes
WHERE tablename IN ('entries', 'chat_sessions', 'chat_sections', 'qa_query_index')
  AND indexname LIKE 'idx_%'
ORDER BY tablename, indexname;
```

### 3. 检查数据填充率

```sql
-- 四层隔离字段统计
SELECT
    'chat_sessions' as table_name,
    COUNT(*) FILTER (WHERE user_id IS NOT NULL) as user_id_count,
    COUNT(*) FILTER (WHERE agent_type IS NOT NULL) as agent_type_count,
    COUNT(*) FILTER (WHERE agent_instance_id IS NOT NULL) as agent_instance_id_count,
    COUNT(*) as total_count
FROM chat_sessions
UNION ALL
SELECT
    'chat_sections' as table_name,
    COUNT(*) FILTER (WHERE user_id IS NOT NULL) as user_id_count,
    COUNT(*) FILTER (WHERE agent_type IS NOT NULL) as agent_type_count,
    COUNT(*) FILTER (WHERE agent_instance_id IS NOT NULL) as agent_instance_id_count,
    COUNT(*) as total_count
FROM chat_sections
UNION ALL
SELECT
    'qa_query_index' as table_name,
    COUNT(*) FILTER (WHERE user_id IS NOT NULL) as user_id_count,
    COUNT(*) FILTER (WHERE agent_type IS NOT NULL) as agent_type_count,
    COUNT(*) FILTER (WHERE agent_instance_id IS NOT NULL) as agent_instance_id_count,
    COUNT(*) as total_count
FROM qa_query_index
UNION ALL
SELECT
    'entries' as table_name,
    COUNT(*) FILTER (WHERE user_id IS NOT NULL) as user_id_count,
    COUNT(*) FILTER (WHERE agent_type IS NOT NULL) as agent_type_count,
    COUNT(*) FILTER (WHERE agent_instance_id IS NOT NULL) as agent_instance_id_count,
    COUNT(*) as total_count
FROM entries;
```

### 4. 检查RLS状态

```sql
-- 检查行级安全策略
SELECT
    schemaname,
    tablename,
    policyname,
    permissive,
    roles,
    cmd,
    qual,
    with_check
FROM pg_policies
WHERE tablename = 'entries';
```

## 🔙 回滚方案

### 1. 删除RLS策略

```sql
DROP POLICY IF EXISTS user_agent_isolation ON entries;
ALTER TABLE entries DISABLE ROW LEVEL SECURITY;
```

### 2. 删除索引

```sql
-- 四层隔离索引
DROP INDEX IF EXISTS idx_entries_user_agent;
DROP INDEX IF EXISTS idx_entries_agent_type_user;
DROP INDEX IF EXISTS idx_entries_section_user_agent;
DROP INDEX IF EXISTS idx_chat_sessions_user_agent;
DROP INDEX IF EXISTS idx_chat_sessions_agent_user;
DROP INDEX IF EXISTS idx_chat_sections_user_agent;
DROP INDEX IF EXISTS idx_chat_sections_agent_user;
DROP INDEX IF EXISTS idx_qa_query_index_user_agent;
DROP INDEX IF EXISTS idx_qa_query_index_agent_user;

-- Knowledge Node 索引
DROP INDEX IF EXISTS idx_entries_scene_tags;
DROP INDEX IF EXISTS idx_entries_space_type;
DROP INDEX IF EXISTS idx_entries_project_code;

```

## ⚠️ 注意事项

1. **备份数据库**: 执行升级前必须备份！
2. **权限要求**: 需要CREATE TABLE和ALTER TABLE权限
3. **执行时间**: 根据数据量，可能需要几分钟到几小时
4. **停机维护**: 建议在低峰期执行，避免影响服务
5. **数据迁移**: 升级脚本会自动迁移现有数据
6. **回滚方案**: 准备好回滚方案，以备不时之需

## 📞 升级支持

如果升级过程中遇到问题，请检查：
1. 数据库连接是否正常
2. 数据库用户权限是否足够
3. 磁盘空间是否充足
4. PostgreSQL版本是否支持（需要12+）
