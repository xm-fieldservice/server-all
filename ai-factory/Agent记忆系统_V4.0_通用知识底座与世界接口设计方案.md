## 1. 设计目标与增量范围

### 1.1 总体目标

在 V3.1.1 的多租户记忆系统基础上，将记忆系统升级为面向“通用知识底座 + 世界接口”的统一平台，满足：

1. **去 Agent 中心化**：不再以“某个具体 Agent 实例”为唯一一等公民，而是抽象出 **通用的来源命名空间（Namespace）与来源标识（SourceIdentifier）**。
2. **通用接入模型**：用 **Note / QA / File / Workflow** 四种标准节点契约，承载绝大部分知识与形态。
3. **全链路工作流追踪**：统一记录 **人-人 / 人-机 / 机-机** 的交互与工作流运行轨迹。
4. **跨源查询与聚合**：构建独立的 **查询路由器（Query Router）**，支持按身份、空间与标签进行动态聚合。
5. **知识再生产**：引入 **KnowledgeOperationLayer**，为数据挖掘、聚类、关系发现提供结构化承载。
6. **动态分类系统**：支持无限层级的路径式分类，适应长期演进。

## 2. 与 V3.1.1 的兼容策略

### 2.1 存储结构兼容

- **保持物理字段不变**：物理层继续使用 `agent_type` 和 `agent_instance_id`。
- **语义升级**：在逻辑层（Code/API）将其映射为 `namespace` 和 `source_identifier`。
- **JSON 扩展**：新要素（Note/Workflow等）的数据约定落在 `extra_meta` 和 `scene_tags` 中，不强制执行 DDL。

## 3. 核心模型定义

### 3.1 命名空间 (Namespace)
- 物理字段：`agent_type`。
- 格式建议：路径式 `app/wechat-note`, `world/github`。

### 3.2 来源标识 (SourceIdentifier)
- 物理字段：`agent_instance_id`。
- 格式建议：实例级 ID，如 `wechat:user_123`。

### 3.3 四要素模型
- **Note**: 笔记/碎片知识。
- **QA**: 问答/高频检索。
- **File**: 文件元数据与切片索引。
- **Workflow**: 工作流节点与交互过程。

## 4. 知识工厂愿景 (Knowledge Factory)

通过 **Ingestion (世界接口) -> Refinement (知识再生产) -> Serving (跨源查询)** 形成完整的知识流水线。
