## 问题清单与解决方案

### 问题1: 数据库连接失败 ❌ → ✅ 已解决

**错误信息**:
```
column "status" does not exist
```

**原因分析**:
- `SessionInfo` 数据类定义了 `status` 和 `updated_at` 字段
- 实际数据库表 `chat_sessions` 不包含这些字段
- SQL 查询引用了不存在的列

**解决方案**:
修改 `session_service.py`，移除不存在的字段：
```python
# 移除了 status 和 updated_at 字段
@dataclass
class SessionInfo:
    session_id: str
    user_id: str
    assistant_id: str
    title: Optional[str]
    metadata: Optional[Dict[str, Any]]
    created_at: datetime
    agent_type: Optional[str]
    agent_instance_id: Optional[str]
```

**影响文件**: `ai_factory/ai_factory/agents/memory/session_service.py`

### 问题2: RLS参数未授权 ❌ → ✅ 已解决

**错误信息**:
```
unrecognized configuration parameter "app.current_user_id"
```

**原因分析**:
- PostgreSQL Row Level Security (RLS) 策略使用自定义参数
- 普通用户 `rag_user` 没有权限设置这些参数
- RLS需要三个参数: `app.current_user_id`, `app.current_agent_type`, `app.current_agent_instance_id`

**解决方案**:

#### 方案1: 诊断RLS配置
创建了诊断脚本 `test_rls_config.py`，测试结果显示：
- ✅ 可以连接数据库
- ✅ 可以设置RLS参数
- ✅ RLS策略已正确配置

**结论**: 数据库配置正常，问题出在应用代码层面

#### 方案2: 修复NULL值处理
**核心问题**: Python `None` 被转换为 PostgreSQL `NULL`，导致RLS检查失败

**RLS策略条件**:
```sql
(user_id = current_setting('app.current_user_id'))
AND (agent_type = current_setting('app.current_agent_type'))
AND (agent_instance_id = current_setting('app.current_agent_instance_id'))
```

**失败原因**:
```
NULL = '' → False (RLS拒绝插入)
```

**修复代码**:
```python
# 修改前
agent_type, agent_instance_id  # 可能是NULL

# 修改后
agent_type or "",  # NULL转为空字符串
agent_instance_id or ""  # NULL转为空字符串
```

**影响文件**: `ai_factory/ai_factory/agents/memory/session_service.py`

### 问题3: 笔记模式走模拟回答 ❌ → ✅ 已解决

**错误现象**:
- 选择笔记模式发送消息
- 仍然返回模拟回答
- 返回的 `mode` 为 `"qa"` 而非 `"note"`

**原因分析**:
内存版API `agent_memory_api_memory.py` 没有区分处理不同模式：
```python
# 旧代码：所有模式都生成模拟回答
answer = f"这是来自记忆系统的模拟回答..."
return {
    "mode": "qa"  # 固定为qa
}
```

**解决方案**:
根据模式实现不同的处理逻辑：
```python
if request.mode in ["qa", "auto"]:
    if is_question:
        # 生成回答
        return {"mode": "qa", "answer": answer, ...}
    else:
        # 仅保存为笔记
        return {"mode": "note", "message": "已保存为笔记", ...}
else:  # note模式
    # 直接保存，不生成回答
    return {"mode": "note", "message": "已保存为笔记", ...}
```

**影响文件**: `ai_factory/ai_factory/web/agent_memory_api_memory.py`

### 问题4: API缺少user_id参数 ❌ → ✅ 已解决

**错误信息**:
```
SessionService.append_message() missing 1 required positional argument: 'user_id'
user_id is required for get_recent_messages
```

**原因分析**:
- V3.1.2 版本引入RLS强制隔离
- `get_recent_messages()` 和 `append_message()` 新增必需参数 `user_id`
- API端点未传入该参数

**解决方案**:
在所有调用前先从数据库获取 `user_id`:

```python
# 修改前
session_service.append_message(
    session_id=session_id,
    role=request.role,
    content=request.content
    # 缺少user_id!
)

# 修改后
with connection_scope() as conn:
    cur.execute("SELECT user_id FROM chat_sessions WHERE session_id = %s", (session_id,))
    user_id = cur.fetchone()[0]

session_service.append_message(
    session_id=session_id,
    role=request.role,
    content=request.content,
    user_id=user_id  # ✅
)
```

**影响文件**: `ai_factory/ai_factory/web/agent_memory_api.py`

**修改的端点**:
1. `GET /api/memory/sessions/{session_id}/messages`
2. `POST /api/memory/sessions/{session_id}/messages`
3. `POST /api/memory/chat`

### 问题5: SessionService缺少get_session方法 ❌ → ✅ 已解决

**错误信息**:
```
'SessionService' object has no attribute 'get_session'
```

**原因分析**:
- API代码调用了 `session_service.get_session(session_id)`
- 实际方法名是 `get_session_info()`
- 且 `get_session_info()` 需要传入 `user_id` 参数

**解决方案**:
直接用SQL查询，避免依赖不存在的方法：

```python
# 修改前
session = session_service.get_session(session_id)
user_id = session.user_id

# 修改后
with connection_scope() as conn:
    with conn.cursor() as cur:
        cur.execute("SELECT user_id FROM chat_sessions WHERE session_id = %s", (session_id,))
        result = cur.fetchone()
        user_id = result[0]
```

**影响文件**: `ai_factory/ai_factory/web/agent_memory_api.py`

## 技术架构说明

### RLS (Row Level Security) 机制

PostgreSQL的行级安全策略，用于实现数据隔离：

```sql
-- 示例策略
CREATE POLICY user_agent_isolation ON chat_sessions FOR ALL
USING (
    user_id = current_setting('app.current_user_id')
    AND agent_type = current_setting('app.current_agent_type')
    AND agent_instance_id = current_setting('app.current_agent_instance_id')
);
```

**隔离维度**:
1. 用户级别 (`user_id`)
2. Agent类型 (`agent_type`)
3. Agent实例 (`agent_instance_id`)

**使用流程**:
```python
# 1. 设置RLS上下文
cur.execute("SET LOCAL app.current_user_id = %s", (user_id,))
cur.execute("SET LOCAL app.current_agent_type = %s", (agent_type or "",))
cur.execute("SET LOCAL app.current_agent_instance_id = %s", (agent_instance_id or "",))

# 2. 执行操作（自动应用RLS过滤）
cur.execute("INSERT INTO chat_sessions ...")
```

### API模式对比

| 特性 | 数据库版 (agent_memory_api.py) | 内存版 (agent_memory_api_memory.py) |
|--------|--------------------------------|-------------------------------------|
| 数据持久化 | ✅ PostgreSQL | ❌ 内存变量 |
| LLM集成 | ✅ DeepSeek/多模型 | ❌ 模拟回答 |
| RAG检索 | ✅ 向量搜索 | ❌ 简化逻辑 |
| 模式区分 | ✅ note/qa/auto | ✅ note/qa/auto |
| 适用场景 | 生产/长期使用 | 快速调试 |

### 三种对话模式

#### 1. 笔记模式 (note)
- 仅保存用户消息到数据库
- 不生成助手回答
- 用于记录知识、待办事项等

#### 2. 问答模式 (qa)
- 直接视为问题
- 执行RAG检索
- 调用LLM生成回答
- 返回助手回答

#### 3. 自动模式 (auto)
- 根据内容智能判断
- 识别疑问词 → 问答模式
- 识别笔记词 → 笔记模式
- 默认为笔记
