## 四、Postgres + pgvector 数据库实例

### 4.1 镜像与版本

- 命令：`docker images`
- 关键输出：
  - `REPOSITORY`: `pgvector/pgvector`
  - `TAG`: `pg16`
- 结论：
  - 本机已拉取并使用 **`pgvector/pgvector:pg16`** 镜像，即 **Postgres 16 + pgvector**。

### 4.2 运行中的容器

- 命令：`docker ps -a`
- 关键输出：
  - 容器名称：`ai-factory-pgvector`
  - 镜像：`pgvector/pgvector:pg16`
  - 端口映射：`0.0.0.0:5433->5432/tcp`
- 结论：
  - 当前有一个名为 **`ai-factory-pgvector`** 的 Postgres+pgvector 容器正在运行。
  - 从宿主机访问 Postgres 时，连接参数为：
    - `host=localhost`
    - `port=5433`

### 4.3 容器环境变量（初始化配置）

- 命令：`docker inspect ai-factory-pgvector --format "{{json .Config.Env}}"`
- 关键环境变量：
  - `POSTGRES_DB=rag_db`
  - `POSTGRES_USER=rag_user`
  - `POSTGRES_PASSWORD=rag_password`
  - `PG_MAJOR=16`
  - `PG_VERSION=16.10-1...`
- 结论：
  - 容器初始化时，默认数据库为 **`rag_db`**，默认用户为 **`rag_user`**。
  - 版本为 **Postgres 16**，与项目配置默认值保持一致（`ai_factory.config.settings.PostgresSettings` 中默认 `port=5433`）。

### 4.4 实际数据库与角色存在性检查

> 所有 SQL 均为只读查询，不修改任何数据。

- 检查数据库列表：
  - 命令：
    - `docker exec ai-factory-pgvector psql -U rag_user -d rag_db -c "SELECT datname FROM pg_database;"`
  - 关键结果：
    - `postgres`
    - `rag_db`
    - `template1`
    - `template0`
  - 结论：
    - **`rag_db` 数据库实际存在**。

- 检查角色列表：
  - 命令：
    - `docker exec ai-factory-pgvector psql -U rag_user -d rag_db -c "SELECT rolname FROM pg_roles;"`
  - 关键结果包括：
    - 多个系统角色（`pg_read_all_data` 等）
    - `rag_user`
  - 结论：
    - **`rag_user` 角色实际存在**。

### 4.5 综述

- 本机通过 Docker 运行的 `ai-factory-pgvector` 容器：
  - 镜像：`pgvector/pgvector:pg16`（Postgres 16 + pgvector）
  - 端口：`localhost:5433` 对应容器内 `5432`
  - 默认数据库：`rag_db`（已存在）
  - 默认用户：`rag_user`（已存在）
- 说明：
  - 用于 RAG 的核心数据库实例已经完成基础初始化（库与账号层面是准备好的）。
  - `rag_db.dump` 是否已完全恢复到该实例，还需在需要时通过表结构/数据进一步确认。

## 六、代码仓库与配置结构（与环境相关部分）

### 6.1 仓库结构（与运行环境强相关的部分）

- 根目录：`d:\AI\ai-factory`
  - `ai_factory/`：核心 Python 包
    - `db/`：数据库访问封装（Postgres/pgvector）
    - `rag/`：RAG 流程与向量检索逻辑
    - `agents/`：各类 Agent 编排逻辑
    - `config/settings.py`：集中管理包括 Postgres 在内的配置
    - 其他：`frameworks/`、`integrations/`、`workflows/`、`web/`、`views/` 等
  - `pyproject.toml`：项目依赖与构建配置
  - `.venv/`：本项目虚拟环境目录
  - `rag_db.dump` / `rag_db_backup_*.dump`：Postgres 数据库导出文件
  - `env.txt`：环境变量模板（需重命名为 `.env`）

### 6.2 配置加载约定

- 模块：`ai_factory.__init__`
  - 在首次导入 `ai_factory` 时自动尝试加载 `.env`：
    - 全局：`D:\AI\.env`（不覆盖已有环境变量）
    - 项目级：`D:\AI\ai-factory\.env`（覆盖前者）

- `env.txt` 中包含的关键变量类别（仅列出类别，不记录具体值）：
  - 时间校准模式相关变量
  - Neo4j 连接信息：`NEO4J_URI`、`NEO4J_USER`、`NEO4J_PASSWORD`
  - Postgres/pgvector 连接信息：`AI_PG_HOST`、`AI_PG_PORT`、`AI_PG_DB`、`AI_PG_USER`、`AI_PG_PASSWORD`
  - LLM / 模型服务：各类 `*_API_KEY`、`*_BASE_URL` 等

> 安全说明：本参照文档**不记录任何实际密钥值**，仅记录变量名称和用途，用于环境搭建与排查。
