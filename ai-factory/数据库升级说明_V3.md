## 一、升级内容概述

### 1.1 四层数据隔离字段添加

为以下4个表添加四层数据隔离字段：

| 表名 | 新增字段 | 说明 |
|------|---------|------|
| **chat_sessions** | `agent_type`, `agent_instance_id` | 会话层隔离 |
| **chat_sections** | `user_id`, `agent_type`, `agent_instance_id` | 片段层隔离 |
| **qa_query_index** | `agent_type`, `agent_instance_id` | Q&A缓存层隔离 |
| **entries** | `user_id`, `agent_type`, `agent_instance_id` | 知识库层隔离 |

### 1.2 Knowledge Node 四级结构字段添加

为 `entries` 表添加Knowledge Node四级结构字段：

| 字段名 | 层级 | 说明 | 是否必填 |
|---------|-------|------|---------|
| `title` | Level 1 | 身份标识，知识节点的标题 | NOT NULL |
| `summary_ai` | Level 2 | 核心语义，参与向量搜索 | 可选 |
| `content` | Level 3 | 事实依据，详细内容 | 可选 |
| `scene_tags` | Level 4 | 场景标签，用于SQL硬过滤 | 可选（JSONB） |
| `extra_meta` | Level 4 | 附加元数据（importance_score等） | 可选（JSONB） |

### 1.3 分类和关联字段添加

| 字段名 | 说明 | 类型 |
|---------|------|------|
| `space_type` | 空间类型（goal/strategy/plan/project/task/topic/note） | TEXT |
| `project_code` | 项目代码 | TEXT |
| `parent_entry_id` | 父节点ID（树形结构） | TEXT（外键） |

### 1.4 冗余字段删除

- 删除 `entries.project_hint`（已迁移到 `extra_meta`）

### 1.5 索引创建

#### 四层隔离索引
- `idx_entries_user_agent`: (user_id, agent_type, agent_instance_id)
- `idx_entries_agent_type_user`: (agent_type, user_id)
- `idx_entries_section_user_agent`: (section_id, user_id, agent_type, agent_instance_id)
- `idx_chat_sessions_user_agent`: (user_id, agent_type, agent_instance_id)
- `idx_chat_sections_user_agent`: (user_id, agent_type, agent_instance_id)
- `idx_qa_query_index_user_agent`: (user_id, agent_type, agent_instance_id)

#### Knowledge Node 索引
- `idx_entries_scene_tags`: GIN索引（scene_tags）
- `idx_entries_space_type`: (space_type, created_at DESC)
- `idx_entries_project_code`: (project_code, created_at DESC)
- `idx_entries_parent`: (parent_entry_id)

### 1.6 RLS行级安全启用

为 `entries` 表启用RLS（行级安全）：
- 策略名称: `user_agent_isolation`
- 隔离逻辑: `user_id = current_setting('app.current_user_id')`

## 二、数据迁移策略

### 2.1 自动数据迁移

升级脚本会自动执行以下数据迁移：

#### chat_sessions → 填充 agent_type
```sql
UPDATE chat_sessions
SET agent_type = assistant_id
WHERE agent_type IS NULL AND assistant_id IS NOT NULL;
```

#### chat_sections → 填充四层隔离字段
```sql
UPDATE chat_sections cs
SET
    user_id = s.user_id,
    agent_type = COALESCE(s.agent_type, s.assistant_id),
    agent_instance_id = s.agent_instance_id
FROM chat_sessions s
WHERE cs.session_id = s.session_id;
```

#### entries → 填充四层隔离字段
```sql
UPDATE entries e
SET
    user_id = cs.user_id,
    agent_type = COALESCE(cs.agent_type, cs.agent_id),
    agent_instance_id = cs.agent_instance_id
FROM chat_sections cs
WHERE e.section_id = cs.section_id;
```

#### project_hint → 迁移到 extra_meta
```sql
UPDATE entries
SET extra_meta = jsonb_set(
    COALESCE(extra_meta, '{}'::jsonb),
    '{project_hint}',
    to_jsonb(project_hint)
)
WHERE project_hint IS NOT NULL;
```

## 四、升级后操作

### 4.1 应用层代码改造

升级完成后，需要修改应用层代码以支持四层数据隔离：

#### 4.1.1 设置RLS上下文变量

在每个请求开始时设置上下文变量：

```python
async def set_rls_context(conn, user_id: str, agent_type: str, agent_instance_id: str):
    """设置RLS上下文变量"""
    await conn.execute(f"SET app.current_user_id = '{user_id}'")
    # 注意：agent_type 和 agent_instance_id 通过应用层过滤，RLS只隔离user_id
```

#### 4.1.2 修改查询语句

所有查询都需要添加四层隔离条件：

```python
# 旧代码（V2）
entries = await conn.fetch("SELECT * FROM entries WHERE content LIKE '%Java%'")

# 新代码（V3）
entries = await conn.fetch("""
    SELECT * FROM entries
    WHERE content LIKE '%Java%'
      AND user_id = $1
      AND agent_type = $2
      AND agent_instance_id = $3
""", user_id, agent_type, agent_instance_id)
```

#### 4.1.3 修改插入语句

插入时需要包含四层隔离字段：

```python
# 旧代码（V2）
await conn.execute("""
    INSERT INTO entries (entry_id, title, content)
    VALUES ($1, $2, $3)
""", entry_id, title, content)

# 新代码（V3）
await conn.execute("""
    INSERT INTO entries (
        entry_id, title, content,
        user_id, agent_type, agent_instance_id
    ) VALUES ($1, $2, $3, $4, $5, $6)
""", entry_id, title, content, user_id, agent_type, agent_instance_id)
```

## 五、回滚方案

### 5.1 回滚SQL脚本

升级脚本的最后包含回滚脚本（已注释）：

```sql
-- 删除RLS策略
DROP POLICY IF EXISTS user_agent_isolation ON entries;
ALTER TABLE entries DISABLE ROW LEVEL SECURITY;

-- 删除索引
DROP INDEX IF EXISTS idx_entries_user_agent;
DROP INDEX IF EXISTS idx_entries_agent_type_user;
DROP INDEX IF EXISTS idx_entries_scene_tags;
...

-- 删除字段（注意：数据会丢失！）
ALTER TABLE entries DROP COLUMN IF EXISTS agent_instance_id;
ALTER TABLE entries DROP COLUMN IF EXISTS agent_type;
ALTER TABLE entries DROP COLUMN IF EXISTS user_id;
ALTER TABLE entries DROP COLUMN IF EXISTS title;
ALTER TABLE entries DROP COLUMN IF EXISTS summary_ai;
...
```

### 5.2 回滚注意事项

⚠️ **回滚会导致数据丢失！**

- 删除字段会丢失该字段的所有数据
- 建议在升级前备份数据库
- 回滚后需要重新导入数据

## 六、常见问题

### Q1: 升级失败怎么办？

**A**:
1. 检查错误日志
2. 确认数据库连接配置正确
3. 确认数据库用户有足够权限（ALTER TABLE, CREATE INDEX等）
4. 确认pgvector扩展已启用

### Q2: 数据迁移不完整怎么办？

**A**:
1. 检查验证输出中的字段填充率
2. 如果填充率低于100%，手动补充数据
3. 示例：`UPDATE entries SET user_id = 'user_123' WHERE user_id IS NULL;`

### Q3: RLS启用后查询变慢怎么办？

**A**:
1. 检查是否创建了四层隔离索引
2. 确认查询语句中包含 user_id 条件
3. 考虑使用 `EXPLAIN ANALYZE` 分析查询计划

### Q4: Knowledge Node 字段填充率低怎么办？

**A**:
1. 新数据会自动包含这些字段（代码改造后）
2. 旧数据可以逐步补充或清理
3. 考虑运行数据清理脚本
