# 向量化统一方案 - 执行指南

## 概述

将原来的 Ollama 向量化方案统一为 DashScope API 方案，实现：
- 统一使用 DashScope text-embedding-v3 模型（1536维）
- 重建 entry_embeddings 表结构
- 一次性全库向量化
- 后续增量更新

## 为什么选择 DashScope？

| 维度 | Ollama本地模型 | DashScope API |
|------|--------------|---------------|
| **稳定性** | 需要本地部署维护 | 云服务，SLA保障 |
| **性能** | 受限于本地硬件 | 高并发，弹性扩容 |
| **部署成本** | 需要GPU/CPU资源 | 零部署成本 |
| **向量维度** | 2560维 | 1536维（小40%） |
| **存储成本** | 高 | 低（小40%） |
| **检索效率** | 慢（维度大） | 快（维度小） |
| **模型更新** | 需手动下载 | 自动更新 |
| **容错重试** | 需自建 | API自带 |

**结论：DashScope API更适合企业级应用。**

## 增量更新机制

### 自动向量化（推荐）

在 `ai_factory/integrations/entries_ingest.py` 中集成自动向量化：

```python
from ai_factory.vectorize_entries_with_ollama import (
    _build_embedding_text,
    upsert_entry_embedding
)
```

**需要修改为：**
```python
from ai_factory.agents.memory.llm_client import get_llm_client

# 获取 entry
entry = {...}

# 生成文本
text = _build_embedding_text(entry)

# 调用 DashScope API
llm_client = get_llm_client()
embedding = llm_client.generate_embedding_sync(text)

# 写入数据库
vector_client.upsert_embedding(entry_id, embedding)
```

### 3. 性能监控

```sql
-- 检查索引使用情况
EXPLAIN ANALYZE
SELECT e.entry_id, e.content, 1 - (emb.embedding <=> %s::vector) AS similarity
FROM entries e
LEFT JOIN entry_embeddings emb ON e.entry_id = emb.entry_id
ORDER BY similarity DESC
LIMIT 10;
```
