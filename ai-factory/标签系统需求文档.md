## 1. 系统概述

### 1.1 标签系统定位

**标签系统是一个独立的、通用的标记工具/底座**

- **独立于Agent记忆系统**：标签系统与记忆系统在逻辑上是分开的
- **通用性**：不仅用于Agent记忆，也适用于通用笔记、知识库等所有场景
- **可扩展性**：作为独立系统，可以独立演进和优化

### 1.2 与Agent记忆系统的关系

```
┌─────────────────────────────────────────────────────────────┐
│                   用户输入层                        │
│  微信笔记、多用户随意输入、啰嗦、不完整                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ↓ (立即)
┌─────────────────────────────────────────────────────────────┐
│            L1: 短期记忆/会话层              │
│  chat_sessions + chat_messages（缓存层）                    │
│  立即存储，不等待打标签                                  │
└─────────────────────────────────────────────────────────────┘
                            │
                            ↓ (异步触发)
┌─────────────────────────────────────────────────────────────┐
│         L2: 标签系统（独立系统）                        │
│  - 标签空间管理（树状结构）                           │
│  - 标签枚举管理                                       │
│  - Agent语义分析（LLM）                                │
│  - 标签匹配与动态创建                                   │
└─────────────────────────────────────────────────────────────┘
                            │
                            ↓ (标签完成后)
┌─────────────────────────────────────────────────────────────┐
│  L3: 大库（entries + entry_embeddings）          │
│  已打标签的条目（scene_tags和space_type已填充）          │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 核心设计原则

1. **标签系统独立于Agent记忆系统**
   - 标签系统作为独立的标记工具/底座
   - 通用性强，可复用于多种场景

2. **标签空间是显性树状结构**
   - 不是完全规则驱动的
   - 树状结构 + 注解 = 完整的标签标记管理空间

3. **Agent作为语义分析执行者**
   - Agent是标签系统的LLM执行者
   - Agent参与整个自动标记机制

4. **先固定后动态**
   - 先建立树状结构（固定部分）
   - 再支持动态标签（动态部分）

5. **完全替代现有scene_tags**
   - 新的标签系统要完全替代现有的三tag
   - 通过接口方式外挂

## 2. 标签空间设计

### 2.1 大循环（固定方法论）

**定义：** 大循环是固定的分类方法论框架

**包含内容：**
- **战略（Strategy）**：战略层面的分类
- **目标（Goal）**：目标的分类和管理
- **计划（Plan）**：计划的分类和管理
- **项目（Project）**：项目的分类和管理

**特点：**
- 是管理工作推动的方法论框架
- 相对固定，变化频率低
- 提供组织管理的顶层视图

### 2.2 小循环（动态标注）

**定义：** 小循环是对大循环工作的标注和记录

**包含内容：**
- **议题（Issue）**：讨论议题的记录
- **任务（Task）**：具体任务的记录
- **笔记（Note）**：日常笔记的记录

**特点：**
- 是对大循环工作的标注和记录
- 动态性强，频繁新增和修改
- 可以独立存在，不必须挂载到大循环节点

**示例：**
- 日程：独立的小循环
- 感慨：独立的小循环
- 临时想法：独立的小循环

### 2.3 部门标签（独立顶级维度）

**定义：** 部门标签是独立的顶级分类维度

**特点：**
- 每个部门有自己的大循环和小循环
- 有层级关系：总部→部门→科室→班组
- 支持跨部门、跨科室的临时项目组和工作流团队

**示例：**
```
总部
├── 软件部
│   ├── 研发科
│   │   ├── 项目组A
│   │   └── 项目组B
│   └── 测试科
├── 市场部
│   ├── 销售科
│   └── 市场科
└── 人力资源部
    ├── 招聘科
    └── 培训科
```

**层级关系说明：**
- "软件部"下的"项目"和"总部"下的"项目"是平行的，没有层级关系
- 部门标签是独立的顶级分类维度，不属于大循环的子分类

### 2.4 Agent驱动的部门与空间绑定

**目标：**

- 将“部门/空间”的选择从用户界面迁移到 Agent 层，由 Agent Profile 决定内容的组织归属；
- 通过 `agent_id` 和 Agent Profile，将每条内容自动挂接到正确的部门节点和标签空间视角。

**设计要点：**

- **Agent 绑定部门节点：**
  - 每个 Agent 在标签系统中绑定到部门树上的一个或多个节点（如“总部/软件部/项目组A”）；
  - 绑定关系可以存储在 Agent Profile 中，并通过接口暴露给标签系统。
- **Agent 绑定标签空间视角：**
  - 每个 Agent 关联一个或多个 `tagging_spaces.space_id`，用于定义其默认工作视角；
  - 不同 Agent 可以共享同一标签空间，也可以有专属空间（如某部门内部项目空间）。
- **自动推导部门/空间标签：**
  - 当 entries / chat_messages / Q&A 由某个 Agent 写入或处理时：
    - 系统根据 `agent_id` 查找对应的部门节点和标签空间；
    - 自动为内容打上部门/空间相关标签，而无需用户在界面上手动选择部门或空间；
  - 对于个人助理型 Agent，可将其绑定到“个人空间”或“私域部门节点”。

**效果：**

- “选择哪个 Agent”即代表“选择在哪个部门/空间视角下工作”；
- 标签系统中的部门维度与 Agent 体系自然对齐，便于按部门/项目/Agent 进行统计与检索；
- 用户不再需要频繁选择部门/空间，降低操作成本，将注意力集中在内容本身。

## 3. 标签枚举设计

### 3.1 标签枚举矩阵

**定义：** 标签枚举是预定义的标签值集合

**结构：**
```
标签枚举矩阵
├── 战略类
│   ├── 战略
│   ├── 目标
│   ├── 计划
│   └── 项目
├── 执行类
│   ├── 议题
│   ├── 任务
│   ├── 笔记
│   └── 其他
├── 状态类
│   ├── 待开始
│   ├── 进行中
│   ├── 已完成
│   └── 已取消
└── 标记类
    ├── 重要
    └── 收藏
```

### 3.2 标签枚举管理

**功能：**
- 标签枚举的增删改查
- 标签枚举的分组管理
- 标签枚举的启用/禁用
- 标签枚举的排序

## 4. 标签规则设计

### 4.1 标签规则定义

**定义：** 标签规则定义了标签空间的结构和约束

**包含内容：**
- 标签空间的树状结构定义
- 标签之间的关系（父子、兄弟）
- 标签的属性（名称、描述、图标、颜色等）
- 标签的约束（是否可删除、是否可修改等）

### 4.2 标签规则版本管理

**版本管理需求：**
- 标签规则需要版本管理
- 规则更新后，旧内容用什么标签需要追溯
- 支持规则的回滚和迁移

**版本管理策略：**
- 树状结构部分（大循环、部门）相对稳定，版本管理
- 动态标签部分频繁更新，需要灵活的版本控制

## 5. Agent语义分析

### 5.1 语义分析输入

**输入内容：**
- 对单条message进行语义分析
- 需要分析以前的上下文（历史标签）

**上下文分析：**
- 需要分析以前的标签，找到类似标记
- 在标签矩阵或标签管理空间里找对应的值
- 找不到就新建标签

### 5.2 语义分析处理流程

**两个独立过程：**

**过程1：Message打标签**
```
输入：单条message
  ↓
Agent语义分析（LLM）
  ↓
在标签空间查找对应标签
  ↓
找到 → 打上标签
找不到 → 新建标签 → 打上标签
```

**过程2：Section汇总**
```
输入：整个section总结
  ↓
Agent语义分析（LLM）
  ↓
汇总多个message的标签
  ↓
可能产生新标签（无法用现有标签概括）
  ↓
打上汇总标签
```

### 5.3 语义空间输出

**Agent输出格式：**
- 自动落地：直接打上标签
- 请示落地：显示建议，等待用户确认

**三种处理方式：**

1. **直接打上（自动模式）**
   - Agent直接在标签空间找到对应值并打上
   - 适用于标签空间清晰、准确度高的情况

2. **每次请求批准（建议模式）**
   - Agent给出标签建议
   - 显示给用户，等待用户确认
   - 适用于前期，特别是标签管理空间建立阶段

3. **全自动模式（后期）**
   - Agent直接打上标签，无需确认
   - 适用于标签空间成熟、信任度高的情况

**默认行为：**
- 如果语义分析失败或不确定
- 系统中断并输出"不确定"标记
- 约定好可以直接打上，则直接打上

## 6. 阈值与匹配

### 6.1 匹配度计算方式

**匹配度计算：**
- 初期：简单的关键词匹配
- 后期：向量相似度计算

**阈值设定：**
- 设定初始值
- 根据实际效果动态调节
- 针对不同场景使用不同阈值

### 6.2 动态标签创建

**创建条件：**
- 匹配度低于阈值时创建新标签
- 新标签需要用户确认（建议模式）或自动创建（自动模式）

**标签加入规则空间：**
- 临时标签：临时使用，可以后续转为永久
- 永久标签：经过确认后加入规则空间
- 标签继承：新标签可以继承父标签的属性

## 7. 用户体验设计

### 7.1 用户参与度

**人机分工：**
- 人：只决策标签管理空间（树状分类）
- Agent/LM：语义分析，自动打标签

**用户参与度：**
- 用户参与打标签过程的意义不大
- 人主要管理标签空间的结构定义
- 语义分析交给Agent/LM，比人分析更准确

### 7.2 标签可视化

**两个概念：**

1. **标签管理空间（树状结构）：**
   - 人看到和修改
   - 标签空间的结构定义
   - 相对稳定，需要可视化的锚点

2. **标签枚举（扁平枚举）：**
   - 用于图表统计
   - 大部分由Agent自动打标签
   - 变化频繁，人看到的意义不大

**可视化的锚点：**
- 标签管理空间的状态（如项目状态）是可视化的锚点
- 即使标签空间变化，修改通道保留
- 用于图表和统计的基准点

### 7.3 标签反馈机制

**反馈机制：**
- 用户可以看到Agent建议的标签
- 用户可以修改Agent的建议标签
- 提供重新打标签的通道

**实际意义：**
- 人主要决策标签管理空间
- Agent/LM负责语义分析和自动打标签
- 反馈机制主要用于特殊情况处理

### 7.4 标签统计与搜索

**统计功能：**
- 标签使用频率统计
- 标签分布统计
- 部门/项目维度的标签统计
- 时间维度的标签趋势分析

**搜索功能：**
- 按标签名称搜索
- 按标签类型搜索
- 按标签层级浏览
- 组合搜索（标签+时间+部门等）

## 8. 系统边界

### 8.1 标签系统的适用范围

**适用范围：**
- entries表：所有内容都需要打标签
- chat_messages表：原始消息也需要打标签
- Q&A缓存：Q&A对也需要标签
- 通用笔记、知识库：任何需要标记的内容

**不适用范围：**
- 纯粹的临时缓存数据
- 系统内部日志

### 8.2 作用域概念

**作用域定义：**
- 公域：所有用户可见的标签
- 私域：特定部门或项目可见的标签
- 视角：同一内容从不同视角可能有不同标签

**作用域管理：**
- 标签空间按作用域组织
- 支持跨域标签查询
- 权限控制

### 8.3 与现有scene_tags的关系

**完全替代：**
- 新的标签系统要完全替代现有的三tag
- scene_tags的键（department, execution, planning等）由标签空间定义

**接口方式：**
- 做一个接口，外挂上
- 标签系统作为通用工具，适用于任何机构

### 8.4 知识本体与关联的非线性增长（知识爆炸）

在全 Agent 化的记忆与标签架构下，每一次写入 entries / chat_messages / Q&A，都不仅仅是“新增一条记录”，而是同时触发两个方向的增长：

- **知识本体的增加**：
  - 新的条目、新的事实、新的规则、新的决策记录被写入大库；
  - 这些本体条目在数量上大体呈线性增长（1、2、3…）。
- **知识关联度的重新生成与增强**：
  - 每次写入都可能与既有条目形成新的关系：引用、例子、反例、修订、上下位、相似等；
  - 随着本体条目的增多，潜在关联关系的组合数呈非线性上升，
    图谱中的边数和可达路径数量会快速放大。

两者叠加，就形成了一个持续的**知识增强过程**：

- 知识本体维度不断变厚；
- 关联结构维度以更快的速度变密；
- 在图谱视角下，这种“本体 + 关联”的双向增长会表现为一种**知识爆炸**现象。

> 预测性需求：
> - 如何在保持表达力和可追溯性的前提下，对这种知识爆炸进行约束和治理，是未来标签系统与图谱治理架构必须正面解决的核心议题之一；
> - 这将直接影响：
>   - 标签空间与图谱的压缩、折叠与抽象能力；
>   - Memory0 等治理模块对“哪些关系该保留、哪些该合并/裁剪”的判断策略；
>   - 双循环治理中，如何通过周期性重构/归档/聚类来“减缓爆炸、保持可用”。

## 9. 数据表设计

### 9.1 标签空间表

```sql
CREATE TABLE IF NOT EXISTS tagging_spaces (
    -- 主键
    space_id VARCHAR(64) PRIMARY KEY,
    
    -- 基本信息
    space_name VARCHAR(128) NOT NULL,
    space_type VARCHAR(32) NOT NULL,  -- 'big_loop' | 'small_loop' | 'department'
    parent_space_id VARCHAR(64),
    
    -- 树状结构
    structure_data JSONB NOT NULL,
    
    -- 元数据
    description TEXT,
    icon VARCHAR(256),
    color VARCHAR(32),
    
    -- 权限控制
    scope VARCHAR(32) DEFAULT 'public',  -- 'public' | 'private' | 'domain'
    allowed_roles VARCHAR(256)[],
    
    -- 版本管理
    version INTEGER DEFAULT 1,
    is_active BOOLEAN DEFAULT TRUE,
    
    -- 时间戳
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- 索引
    INDEX idx_parent_space_id (parent_space_id),
    INDEX idx_space_type (space_type),
    INDEX idx_scope (scope),
    INDEX idx_is_active (is_active)
);

COMMENT ON TABLE tagging_spaces IS '标签空间表，定义标签的树状结构和元数据';
```

### 9.2 标签枚举表

```sql
CREATE TABLE IF NOT EXISTS tag_enums (
    -- 主键
    enum_id VARCHAR(64) PRIMARY KEY,
    
    -- 基本信息
    enum_name VARCHAR(128) NOT NULL,
    enum_value VARCHAR(128) NOT NULL,
    enum_label VARCHAR(128) NOT NULL,
    
    -- 分组
    category VARCHAR(64) NOT NULL,
    group_name VARCHAR(128),
    sort_order INTEGER DEFAULT 0,
    
    -- 所属空间
    space_id VARCHAR(64) NOT NULL,
    
    -- 属性
    color VARCHAR(32),
    icon VARCHAR(256),
    
    -- 状态
    is_active BOOLEAN DEFAULT TRUE,
    
    -- 时间戳
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- 索引
    INDEX idx_space_id (space_id),
    INDEX idx_category (category),
    INDEX idx_is_active (is_active)
);

COMMENT ON TABLE tag_enums IS '标签枚举表，定义预定义的标签值';
```

### 9.3 标签规则表

```sql
CREATE TABLE IF NOT EXISTS tagging_rules (
    -- 主键
    rule_id VARCHAR(64) PRIMARY KEY,
    
    -- 基本信息
    rule_name VARCHAR(128) NOT NULL,
    rule_type VARCHAR(32) NOT NULL,  -- 'structure' | 'constraint' | 'permission'
    rule_data JSONB NOT NULL,
    
    -- 所属空间
    space_id VARCHAR(64) NOT NULL,
    
    -- 版本管理
    version INTEGER DEFAULT 1,
    is_active BOOLEAN DEFAULT TRUE,
    
    -- 时间戳
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- 索引
    INDEX idx_space_id (space_id),
    INDEX idx_rule_type (rule_type),
    INDEX idx_is_active (is_active)
);

COMMENT ON TABLE tagging_rules IS '标签规则表，定义标签空间的结构和约束';
```

### 9.4 消息标签关联表

```sql
CREATE TABLE IF NOT EXISTS message_tags (
    -- 主键
    tag_id VARCHAR(64) PRIMARY KEY,
    
    -- 消息关联
    message_id VARCHAR(64) NOT NULL,
    session_id VARCHAR(64),
    
    -- 标签信息
    enum_id VARCHAR(64),  -- 引用tag_enums
    space_id VARCHAR(64),  -- 引用tagging_spaces
    tag_path VARCHAR(512),  -- 标签路径（如：总部/软件/项目）
    
    -- 匹配信息
    match_score DECIMAL(5, 4),
    match_method VARCHAR(32),  -- 'keyword' | 'vector' | 'llm'
    
    -- 创建信息
    created_by VARCHAR(64),  -- 'agent' | 'user'
    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- 索引
    INDEX idx_message_id (message_id),
    INDEX idx_session_id (session_id),
    INDEX idx_enum_id (enum_id),
    INDEX idx_space_id (space_id),
    INDEX idx_created_at (created_at)
);

COMMENT ON TABLE message_tags IS '消息标签关联表，记录消息与标签的关系';
```

### 9.5 标签统计表

```sql
CREATE TABLE IF NOT EXISTS tag_statistics (
    -- 主键
    stat_id VARCHAR(64) PRIMARY KEY,
    
    -- 统计维度

    created_at TIMESTAMP WITH TIME ZONE NOT NULL DEFAULT CURRENT_TIMESTAMP,
    
    -- 索引
    INDEX idx_stat_date (stat_date),
    INDEX idx_stat_type (stat_type),
    INDEX idx_dimension (dimension)
);

COMMENT ON TABLE tag_statistics IS '标签统计表，记录标签的使用和分布情况';
```

### 10.2 核心设计原则

1. **标签系统独立于Agent记忆系统**
   - 标签系统作为独立的标记工具/底座
   - 通用性强，可复用于多种场景

2. **标签空间是显性树状结构**
   - 不是完全规则驱动的
   - 树状结构 + 注解 = 完整的标签标记管理空间

3. **Agent作为语义分析执行者**
   - Agent是标签系统的LLM执行者
   - Agent参与整个自动标记机制

4. **先固定后动态**
   - 先建立树状结构（固定部分）
   - 再支持动态标签（动态部分）

5. **完全替代现有scene_tags**
   - 新的标签系统要完全替代现有的三tag
   - 通过接口方式外挂

### 10.3 风险与缓解

**风险：**
- 标签系统与记忆系统的集成复杂度
- 异步打标签的时序问题
- 标签准确性的挑战

**缓解措施：**
- 渐进式实施，先实现基础功能
- 充分的测试和验证
- 提供手动干预和调整机制
- 完善的监控和日志
