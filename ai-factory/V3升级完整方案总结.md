# V3多租户架构升级完整方案总结

## 📋 方案概述

本方案解决了V3多租户架构升级过程中遇到的问题，提供了完整的升级流程和多种执行方式。

### 🎯 解决的问题

1. ✅ **权限不足问题**：`rag_user` 缺乏 CREATE TABLE 和 ALTER TABLE 权限
2. ✅ **缺失表问题**：`chat_sessions`, `chat_sections`, `qa_query_index` 不存在
3. ✅ **缺失字段问题**：`entries` 表缺少 `agent_type`, `agent_instance_id` 字段
4. ✅ **数据迁移问题**：自动从现有数据填充四层隔离字段
5. ✅ **索引优化问题**：创建13个高性能索引
6. ✅ **数据隔离问题**：启用RLS行级安全策略

## 📞 问题排查

### 问题1：连接数据库失败

**原因**：
- 数据库服务未启动
- 用户名或密码错误
- 数据库不存在

**解决**：
```bash
# 检查数据库状态
docker ps | grep postgres
# 或
systemctl status postgresql

# 测试连接
psql -h localhost -p 5433 -U postgres -d rag_db
```

### 问题2：权限不足

**原因**：
- 用户缺乏 CREATE TABLE 权限
- 用户缺乏 ALTER TABLE 权限

**解决**：
```sql
-- 授予权限（需要超级用户）
GRANT ALL PRIVILEGES ON DATABASE rag_db TO postgres;
GRANT ALL PRIVILEGES ON SCHEMA public TO postgres;
```

### 问题3：表已存在

**原因**：
- 重复执行升级脚本

**解决**：
- 升级脚本使用 `IF NOT EXISTS`，会自动跳过已存在的表和字段
- 可以安全地重复执行

### 问题4：索引创建失败

**原因**：
- pgvector扩展未安装
- 索引名称冲突

**解决**：
```sql
-- 检查pgvector扩展
SELECT * FROM pg_extension WHERE extname = 'vector';

-- 安装pgvector（如果未安装）
CREATE EXTENSION IF NOT EXISTS vector;
```
