## 一、三维需求体系说明

### 1.1 三维定义

| 维度 | 视角 | 描述方式 | 图谱表达 |
|------|------|----------|----------|
| **第1维** | 用户视角 | 面板→功能（线性） | Panel -[:DISPLAYS]-> Feature |
| **第2维** | 模块视角 | 模块→辐射（去中心化） | Module -[:CONTAINS]-> Feature |
| **第3维** | 关系视角 | 动态关联（深度边界） | Feature -[:DEPENDS_ON]-> Feature |

### 1.2 第四层：决策层

```
基于三维需求图谱，实现：
1. 自举式开发：找出"最小依赖、最大价值"的功能作为起点
2. 动态优先级：每完成一个功能，重新评估影响，确定下一个
3. 渐进交付：不追求"从一而终"，而是动态调整
```

### 4.2 关系类型定义

| 关系类型 | 说明 | 示例 |
|----------|------|------|
| `DEPENDS_ON` | 强依赖 | M3脑图 DEPENDS_ON M2 AI工厂 |
| `USES` | 使用 | M4项目管理 USES M5 Agent货架 |
| `BELONGS_TO` | 属于 | M3脑图 BELONGS_TO M4项目管理 |
| `ACCESSED_BY` | 被访问 | M7关系管理 ACCESSED_BY M6企微 |
| `PROVIDES_DATA_TO` | 提供数据 | M6企微 PROVIDES_DATA_TO M8个人档案 |
| `INTEGRATES_WITH` | 集成 | M6企微 INTEGRATES_WITH M1数据层 |

## 五、Neo4j 图谱 Schema

### 5.1 节点标签

```cypher
// 系统层
CREATE CONSTRAINT system_id IF NOT EXISTS FOR (s:System) REQUIRE s.id IS UNIQUE;

// 模块层
CREATE CONSTRAINT module_id IF NOT EXISTS FOR (m:Module) REQUIRE m.id IS UNIQUE;

// 功能层
CREATE CONSTRAINT feature_id IF NOT EXISTS FOR (f:Feature) REQUIRE f.id IS UNIQUE;

// 面板层
CREATE CONSTRAINT panel_id IF NOT EXISTS FOR (p:Panel) REQUIRE p.id IS UNIQUE;

// API层
CREATE CONSTRAINT api_id IF NOT EXISTS FOR (a:API) REQUIRE a.id IS UNIQUE;

// 数据实体层
CREATE CONSTRAINT entity_id IF NOT EXISTS FOR (e:Entity) REQUIRE e.id IS UNIQUE;

// 角色层
CREATE CONSTRAINT role_id IF NOT EXISTS FOR (r:Role) REQUIRE r.id IS UNIQUE;
```

### 5.2 关系类型

```cypher
// 模块关系
(:System)-[:CONTAINS]->(:Module)
(:Module)-[:CONTAINS]->(:Feature)
(:Module)-[:DEPENDS_ON]->(:Module)
(:Module)-[:USES]->(:Module)
(:Module)-[:INTEGRATES_WITH]->(:Module)

// 功能关系
(:Feature)-[:BELONGS_TO]->(:Module)
(:Feature)-[:DEPENDS_ON]->(:Feature)
(:Feature)-[:TRIGGERS]->(:API)
(:Feature)-[:USES]->(:Entity)
(:Feature)-[:ACCESSED_BY]->(:Role)

// 面板关系
(:Panel)-[:DISPLAYS]->(:Feature)
(:Panel)-[:ACCESSED_BY]->(:Role)

// 数据关系
(:Module)-[:READS]->(:Entity)
(:Module)-[:WRITES]->(:Entity)
```

## 六、动态开发决策（第4层）

### 6.1 自举式开发算法

```python
def find_next_feature():
    """
    找出下一个最优开发功能
    评估标准：
    1. 依赖已满足（或无依赖）
    2. 被依赖数最多（解锁最多后续功能）
    3. 用户价值最高
    """
    query = """
    MATCH (f:Feature {status: 'pending'})
    WHERE NOT (f)-[:DEPENDS_ON]->(:Feature {status: 'pending'})
    OPTIONAL MATCH (f)<-[:DEPENDS_ON]-(dependent:Feature)
    RETURN f, count(dependent) as dependents, f.priority as priority
    ORDER BY dependents DESC, priority DESC
    LIMIT 1
    """
    return execute_query(query)

def update_impact(completed_feature_id):
    """
    完成一个功能后，更新影响分析
    """
    query = """
    MATCH (f:Feature {id: $id})-[:AFFECTS]->(impacted)
    SET f.status = 'completed'
    RETURN impacted
    """
    return execute_query(query, id=completed_feature_id)
```

### 6.2 优先级评估维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 依赖满足度 | 30% | 所有依赖是否已完成 |
| 解锁价值 | 25% | 解锁多少后续功能 |
| 用户价值 | 25% | 直接用户价值 |
| 实现成本 | 20% | 开发工作量 |
